# Annual Report RAG API

A local-first, citation-grounded API for asking questions about annual reports. The included Northstar Components report is synthetic and exists only for repeatable tests; do not present its figures as real company information.

## What it does

- Ingests PDF, TXT, and Markdown reports, splits text into overlapping chunks, and indexes normalized hashed-token embeddings in persistent Chroma.
- Runs a LangGraph retrieve → answer → citation-verification workflow. The default answerer is extractive: it returns a matching source sentence or abstains instead of inventing an answer.
- Exposes FastAPI endpoints for document ingestion, Q&A, health, and aggregate request/token/estimated-cost metrics.
- Includes a ten-question synthetic evaluation and Docker / GitHub Actions setup.

The hash-based embedder and extractive answerer are deterministic demo defaults, not substitutes for a semantic embedding model or production LLM. They avoid credentials and external model downloads. To enable the optional Amazon Bedrock Converse integration, set `BEDROCK_MODEL_ID` and AWS credentials/region. The model is constrained to return a verbatim report sentence; responses that do not exactly match a retrieved source sentence are rejected. Set input/output per-1K-token rates to estimate cost. With the default extractive mode, model cost is zero.

## Run locally

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
uvicorn app.api:app --reload
```

In another terminal:

```powershell
Invoke-RestMethod -Uri http://localhost:8000/documents -Method Post -Form @{ file = Get-Item .\data\demo\fictional_annual_report.md }
Invoke-RestMethod -Uri http://localhost:8000/ask -Method Post -ContentType "application/json" -Body '{"question":"What was revenue in fiscal year 2024?"}'
Invoke-RestMethod http://localhost:8000/metrics
```

Interactive API documentation: <http://localhost:8000/docs>.

## Evaluate

```powershell
python scripts/evaluate.py
pytest
```

Evaluation sweeps chunk sizes (500, 900, 1300 characters) and top-k values (2, 4), then selects the best answer accuracy, citation faithfulness, and retrieval recall; ties prefer fewer retrieved chunks and smaller chunks. On the checked-in 10-question fixture, the selected setting is **500-character chunks / top-2**:

| Metric | Result |
|---|---:|
| Answer accuracy | 100% (10/10) |
| Citation faithfulness | 100% (10/10) |
| Retrieval recall@2 | 100% (10/10) |

These are synthetic single-report benchmark results, not an estimate of real-world annual-report QA performance. `evaluation-results.json` is generated by the evaluation script.

## API

- `POST /documents`: multipart upload with field `file`; supports `.pdf`, `.txt`, `.md`.
- `POST /ask`: JSON `{"question":"...", "top_k":4}`; response includes answer, citations, abstention, latency, tokens, and estimated USD cost. Token, latency, cost, and abstention metrics are also emitted to the application logger.
- `GET /health`: service status and indexed chunk count.
- `GET /metrics`: request count, cumulative token estimates, average latency, and estimated costs since process start.

## Production considerations

Set a durable Chroma volume, configure authentication and network controls, use an approved real embedding/LLM provider, and calibrate per-model pricing before deploying. The demo hash embedder is not intended for high-quality semantic search. Metrics are in-memory and reset on restart; use a metrics backend for production. Upload size is limited, but production deployments should add stronger content validation and access controls.
